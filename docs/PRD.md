## 一、产品概述

### 1.1 产品背景

纸质小票易丢失、褪色、破损，用户日常消费、报销、生活纪念小票难以长期留存；个人用户需要一款纯私密、无社交、无信息泄露风险的小程序，实现小票快速录入、分类归档、事件整合、数据统计与便捷导出，满足小票收藏、报销记账、消费记录等核心需求。

### 1.2 产品定位

**纯个人私密电子小票管理工具**，聚焦小票数字化收藏、分类、事件整合、统计、导出核心场景，全程无用户社交互动、无公共数据分享、无第三方数据上传，保障用户小票数据绝对隐私安全，适配个人开发者轻量开发、快速上线。

### 1.3 核心价值

1. **纸质小票数字化**：拍照/相册随时记录，永久留存不丢失。
2. **零图片依赖与极致轻量**：采用 100% 纯矢量 SVG Data-URI + Canvas 2D 图表，全工程仅 200KB 左右，极速加载，不超微信 2MB 主包限制。
3. **100% 纯本地隐私安全**：数据全部存储在用户设备 `wx.Storage`，绝无后台云端收集。
4. **轻量化手账体验**：温润手账森系调色，支持分类归档、事件贴纸、多维统计。
5. **合规无多余权限**：无社交、无广告、无多余授权、极简使用。

### 1.4 核心禁忌（个人开发者合规红线）

- 无任何用户社交功能（无好友、无分享、无广场、无互动）。
- 无强制用户注册、无手机号 / 身份证等敏感信息收集。
- 无小票数据公共上传、无第三方数据共享。
- 无多余权限获取，仅申请核心功能必要权限（相机、相册、本地存储）。

## 三、技术实现架构与目录结构

### 3.1 最新技术选型

| 层级 | 技术选型 | 说明 |
|---|---|---|
| **开发框架** | 微信小程序原生框架 | 零第三方重型依赖，启动快 |
| **编程语言** | JavaScript (ES6+ / CommonJS) | 规范模块化拆分 |
| **UI 图标系统** | **纯矢量内联 SVG (Data-URI)** | `data:image/svg+xml;utf8,...` 原生支持，零位图图片文件 |
| **图表可视化** | **Canvas 2D API + CSS** | 原生 Canvas 2D 绘制高精度环形图，CSS 渲染响应式柱状趋势 |
| **样式系统** | WXSS + CSS 变量 (`tokens.wxss`) | 温润手账莫兰迪调色系统，支持安全区适配 |
| **性能优化** | **按需注入 / 用时注入** (`lazyCodeLoading`) | `"requiredComponents"` 仅在进入页面时注入对应代码与组件，降低冷启动耗时 |
| **数据持久化** | `wx.getStorageSync` / `wx.setStorageSync` | 100% 手机本地存储，绝不外传 |

## 四、后续版本迭代路线图 (Roadmap)

### 阶段 1：真机能力接入与真实导出 (V1.3 规划)
- [ ] **接入真实 OCR**：对接微信小程序服务市场 OCR 插件（如印刷发票识别/通用印刷体识别），保留本地 Mock 作为 Fallback。
- [ ] **真实 PDF / Excel 导出**：
  - PDF：基于 Canvas 动态绘制排版后导出图片或调用原生能力转 PDF。
  - Excel：在前端组装 CSV / 表格数据并通过 `wx.saveFileToDisk` 保存至手机。
- [ ] **数据导入恢复真实对接**：通过 `wx.chooseMessageFile` 选择聊天记录中的 JSON 备份文件一键恢复。

### 阶段 2：交互丰富与手账特色增强 (V1.4 规划)
- [ ] **事件手账翻页动画**：为小票事件生成可翻页浏览的动态手账小相册。
- [ ] **全局多主题联动**：打通 `tokens.wxss` 与 `app.wxss`，使「米白手账」、「薄荷小屋」、「夜读深色」主题全页面实时换肤生效。
- [ ] **生物识别集成**：评估接入 `wx.checkIsSupportSoterAuthentication`，支持指纹/FaceID 解锁启动。
- [ ] **小票防重校验**：录入保存时对同日期、同商家、同金额的小票进行智能相似度提示。

### 阶段 3：长期合规与性能保障
- 始终坚持 **无社交、零数据上传、纯本地隐私、超轻量化** 的产品底线，满足个人开发者合规上架标准。
